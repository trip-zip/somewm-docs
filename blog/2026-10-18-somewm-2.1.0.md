TL;DR

SomeWM 2.1 changes how the compositor builds a frame. Clients and widgets now go through one layout engine in C, followed by one renderer that applies the result to the scene. Rounded corners, new animation library, and a desktop inspector get rolled in with those changes.

I never wrote a release announcement for 2.0, so here's a tiny summary. That release rebuilt the C-to-Lua event boundary; 2.1 rebuilds the layout and rendering path. Together, they give state changes, layout and drawing an explicit order in the main loop.

*I'm trying something just to be a bit extra.  All the widget diagrams and animation demos in this post are captured from live SomeWM 2.1 widgets. Open “Show Lua” beneath a capture for the complete code to try it yourself.*

## New in 2.1

- **A single layout and rendering pipeline.** Dirty outputs are declared as Clay trees, solved in C, then handed to the renderer as commands. Bars, widgets and client frames follow the same path.
- **Rounded client corners and frames that fit.** Set `c.shape = 12` for a 12-pixel radius. Titlebars share the corners, and decorations follow the size the application actually draws.
- **Patched wlroots.** I added the rounded clipping that wlroots 0.20.2 lacked, including pointer hit-testing that respects the cut corners. SomeWM builds the patched version automatically, with rendering support in GLES2 and pixman.
- **[Composable animations](/docs/guides/animation).** Clients, wiboxes, popups and widgets have animation policies. Eleven entrance effects include five new scale effects; combine a scale, a slide and a fade.
- **A desktop inspector.** Set `screen.primary.inspector = true` to browse the element tree and inspect solved boxes. Style it through `beautiful.inspector_*`.
- **Lock screen wallpaper.** Set `theme.lockscreen_wallpaper` and `theme.lockscreen_wallpaper_overlay` for a letterboxed image with an overlay.
- **Scrollable hotkeys help and menubar.** Long lists scroll instead of paging.

**Existing configurations need a migration check.** SomeWM still loads your `rc.lua` and supports composition from stock `wibox` widgets. Custom widgets that implement their own `draw`, `fit` or `layout` methods are omitted, along with their children. Third-party widgets using those methods need updates. Read the [upgrade guide](/docs/getting-started/upgrading-from-2.0) before switching.

## 2.0 rebuilt the C and Lua boundary

The 2.0 work reached across the compositor's C-to-Lua boundary: event delivery, object bindings and the lifecycle of the Lua state during reloads. I also split the C core into focused modules. The aim was to give state changes and configuration code a predictable order of execution.

A C event handler could previously emit a notification and immediately enter Lua. A Lua handler could change another property and call back into C before the original operation had finished. Geometry, focus and input handling all had to account for that back-and-forth.

The queue moves those notifications to a deliberate hand-off point. C records them, then `some_refresh()` delivers a batch to Lua before running refresh work. Repeated pointer moves can be combined, and newly queued notifications wait for the next drain. Requests whose answers C needs immediately remain synchronous, as do Lua-emitted signals.

## 2.1 rebuilds the path from state to pixels

Layout used to be spread across several mechanisms. Client layouts calculated rectangles in Lua. Widgets answered `fit` and `layout` calls and painted into Cairo surfaces. C then had to position those surfaces and the clients in the scene. Each mechanism was responsible for a different part of the desktop's geometry.

In 2.1, those native layout paths describe relationships: a bar has a height, the workarea takes the space below it, and a master client takes a share of that workarea. Widgets describe their content, padding, gaps and sizing rules. **Clay computes the resulting sizes and positions together in C.**

![Four numbered cards rendered by SomeWM: declare the output tree, solve its layout in Clay, reconcile the scene, and present it through wlroots.](/img/architecture/clay-frame-pipeline-somewm.png)

Changing a widget property marks work for that stage. A widget no longer paints its own surface as part of handling the change. Cairo is still used for raster content such as text and paths, under the renderer's control. Applications still supply their own surface pixels.

## Corners and client sizes

With `c.shape = 16`, a left titlebar takes the left corners and the application surface takes the right ones. Clicks in the cut corners reach what is below.

The frame also follows the client's committed size. A terminal that keeps whole character cells gets a titlebar, border and shadow around those cells. Its frame no longer overhangs the content to fill the last few pixels of its tiled slot.

```lua
local options = ... or {}
local awful = require("awful")
local beautiful = require("beautiful")
local gears = require("gears")
local ruled = require("ruled")
local wibox = require("wibox")

assert(not _G.somewm_rounded_terminals or not _G.somewm_rounded_terminals.running,
    "Close the existing terminal demo first")
local target = awful.screen.focused()
if options.output then target = assert(output.get_by_name(options.output), "Output not found").screen end
local token = "somewm-rounded-" .. tostring({}):match("0x(%x+)")
local state = { running = true, ready = false, clients = {}, previous_tags = target.selected_tags }
_G.somewm_rounded_terminals = state
state.tag = awful.tag.add("corners", {
    screen = target,
    layout = awful.layout.suit.tile,
    master_width_factor = 0.56,
    master_count = 1,
    column_count = 1,
    gap = 14,
})

function state.stop()
    if not state.running then return end
    state.running = false
    if state.timer then state.timer:stop() end
    ruled.client.remove_rule(token)
    for _, c in ipairs(state.clients) do if c.valid then c:kill() end end
    if #target.selected_tags == 1 and state.tag.selected then
        awful.tag.viewmore(state.previous_tags, target)
    end
    local attempts = 0
    gears.timer.start_new(0.1, function()
        attempts = attempts + 1
        if #state.tag:clients() == 0 then state.tag:delete(); return false end
        return attempts < 30
    end)
end

local function decorate(c)
    state.clients[#state.clients + 1] = c
    c.shape = 16
    c.border_width = 0
    c.size_hints_honor = true
    c.animation = false
    for _, edge in ipairs({ "top", "right", "bottom" }) do
        awful.titlebar.hide(c, edge)
    end
    awful.titlebar(c, {
        position = "left",
        size = 24,
        bg_normal = "#3c3836",
        bg_focus = "#504945",
        fg_normal = beautiful.fg_normal,
        fg_focus = beautiful.fg_normal,
    }):setup {
        {
            awful.titlebar.widget.closebutton(c),
            margins = 4,
            widget = wibox.container.margin,
        },
        {
            {
                awful.titlebar.widget.titlewidget(c),
                direction = "west",
                widget = wibox.container.rotate,
            },
            halign = "center",
            valign = "center",
            widget = wibox.container.place,
        },
        nil,
        layout = wibox.layout.align.vertical,
    }
    if #state.clients == 3 then
        gears.timer.delayed_call(function()
            for i = 1, 3 do
                local ordered = {}
                for _, candidate in ipairs(client.get(target)) do
                    if candidate.class and candidate.class:sub(1, #token) == token then
                        ordered[#ordered + 1] = candidate
                    end
                end
                for _, owned in ipairs(state.clients) do
                    if owned.class == token .. "-" .. i and owned ~= ordered[i] then
                        owned:swap(ordered[i])
                    end
                end
            end
            state.ready = true
        end)
    end
end

local classes = { token .. "-1", token .. "-2", token .. "-3" }
ruled.client.append_rule {
    id = token,
    rule_any = { class = classes },
    properties = {
        screen = target, tag = state.tag, focus = false, switchtotag = false,
        floating = false, border_width = 0, shape = 16, size_hints_honor = true,
    },
    callback = decorate,
}
if options.select ~= false then state.tag:view_only() end
local bg = (beautiful.bg_normal or "#282828"):gsub("#", "")
local fg = (beautiful.fg_normal or "#ebdbb2"):gsub("#", "")
for i = 1, 3 do
    local argv = {
        "foot", "--app-id=" .. classes[i],
        "--title=" .. (options.titles and options.titles[i] or "Terminal " .. i),
        "--font=monospace:size=15",
        "--override=colors-dark.background=" .. bg,
        "--override=colors-dark.foreground=" .. fg,
        "--override=pad=12x12",
    }
    if options.commands and options.commands[i] then
        argv[#argv + 1] = "--hold"
        for _, arg in ipairs(options.commands[i]) do argv[#argv + 1] = arg end
    end
    local pid = awful.spawn(argv, false)
    if type(pid) ~= "number" then state.stop(); error(tostring(pid)) end
end
state.timer = gears.timer.start_new(600, function() state.stop(); return false end)
return "Three terminals opening on screen " .. target.index
```

```lua
local beautiful = require("beautiful")
local gears = require("gears")
local g = screen.primary.geometry
beautiful.lockscreen_wallpaper = gears.surface.crop_surface {
    surface = gears.surface.load_uncached(
        os.getenv("HOME") .. "/wallpapers/gruvbox/spaceman.jpg"

    ratio = g.width / g.height,

beautiful.lockscreen_wallpaper_overlay = "#00000055"
```

The final two hex digits control the overlay's opacity; `55` is about one-third opacity. The [lock screen guide](/docs/guides/lockscreen) covers the other settings.

## Why Clay

I wanted one sensible layout engine, running in C. Clients and widgets had separate ways of working out sizes and positions. [Clay](https://github.com/nicbarker/clay) was a chance to simplify how the whole desktop is laid out.

For a closer look at Clay itself, Nic Barker's video [How Clay's UI Layout Algorithm Works](https://www.youtube.com/watch?v=by9lQvpvMIc) explains how it sizes and places elements.

Existing custom **client layouts** with an `arrange` function still work through the compatibility path. Custom widget `draw`, `fit` and `layout` methods need migration; see the [widget migration example](/docs/concepts/widgets-in-the-tree).

The [changelog](https://github.com/trip-zip/somewm/blob/main/CHANGELOG.md) has the full list of changes.

## Where we go next

Next I want to bring in Elv13's tree work from [awesome-1](https://github.com/Elv13/awesome-1). The intended split is an `awful` tree for compositor state, with Clay responsible for layout computation.

I also want the debug inspector to be fully live and editable, like a browser's developer tools. You should be able to change Clay properties directly in the inspector and immediately see the changes on your desktop.

For a future major release, probably 3.0, I want to overhaul widget and client creation around a single native Clay syntax. I explored that approach in [Kiln](/kiln/); for SomeWM, I want to take it further in performance and usability. 2.1 unifies layout computation. That release would unify how you describe the desktop.

Try it with your own configuration and [report any issues on GitHub](https://github.com/trip-zip/somewm/issues).
